# MSAs — provenance

Multiple sequence alignments for **residue-conservation analysis** (per-column
conservation vs. per-site model disagreement / functional annotations). The MSA
files themselves are **git-ignored** (large); only this provenance note is tracked.

## Source
**ProteinGym v1.3** substitution-benchmark MSAs (`DMS_msa_files.zip`), downloaded
from the Marks Lab:

```bash
VERSION="v1.3"
FILENAME="DMS_msa_files.zip"
curl -o ${FILENAME} https://marks.hms.harvard.edu/proteingym/ProteinGym_${VERSION}/${FILENAME}
unzip ${FILENAME} && rm ${FILENAME}
```

### Sequence weights (theta reweighting)

Per-sequence reweighting vectors used for weighted conservation (`DMS_msa_weights/`,
`*.npy`, one per assay via `weight_file_name` in `DMS_substitutions.csv`):

```bash
VERSION="v1.3"
FILENAME="DMS_msa_weights.zip"
curl -o ${FILENAME} https://marks.hms.harvard.edu/proteingym/ProteinGym_${VERSION}/${FILENAME}
unzip ${FILENAME} && rm ${FILENAME}
```

Each weight vector aligns to the **EVE-filtered** sequence set (sequences whose
gap fraction over focus columns exceeds 0.5, or that carry non-standard residues,
are dropped), so it is shorter than the raw `.a2m` record count. Script 28
reproduces that filtering to pair weights with sequences; the weighted per-column
amino-acid frequency is `sum(w_s · 1[seq_s has aa i]) / sum(w_s over non-gap)`,
i.e. `N_eff = sum(w_s)` effective sequences instead of the raw count.

One alignment per protein, `.a2m` format, named `<UniProt_ID>_b<bitscore>.a2m`
(e.g. `HXK4_HUMAN_b0.1.a2m`), generated by a per-protein homology search with a
bitscore threshold chosen per protein, then 80%-identity sequence reweighting
(theta = 0.2) for the effective-depth statistics. These match the `MSA_*` metadata
columns in `DMS_substitutions.csv` (below).

## Per-protein parameters (already in the repo)
Every assay's MSA parameters are recorded in
`../../../ProteinGym/reference_files/DMS_substitutions.csv`, columns:

| column | meaning |
|---|---|
| `MSA_filename` | MSA file for this protein (e.g. `HXK4_HUMAN_b0.1.a2m`) |
| `MSA_start` / `MSA_end` / `MSA_len` | aligned region (UniProt coords) and length |
| `MSA_bitscore` | per-protein search bitscore threshold (also in the filename) |
| `MSA_theta` | reweighting identity threshold for N_eff (0.2 = cluster at 80% id) |
| `MSA_num_seqs` | number of sequences in the alignment |
| `MSA_perc_cov` / `MSA_num_cov` | fraction / count of columns above the coverage cutoff |
| `MSA_N_eff` | effective number of sequences (reweighted) |
| `MSA_Neff_L` | N_eff per length; `MSA_Neff_L_category` = Low / Medium / High |
| `MSA_num_significant` / `_L` | significant EVcouplings pairs (count / per length) |

Example (HXK4_HUMAN): `HXK4_HUMAN_b0.1.a2m`, region 1–465, bitscore 0.1, theta 0.2,
23,354 sequences, 100% coverage, N_eff 2,318.4, Neff_L 4.99 (Medium).

## Notes for the conservation analysis
- **Coordinate mapping.** Conservation is per-MSA-column; map columns → our `up_pos`
  / assay numbering using the query sequence in the alignment (the same offset
  handling in scripts 15/22/23), watching for isoform differences (KRAS 4A/4B, the
  off-by-one proteins).
- **Depth caveat.** `MSA_Neff_L` (both tails) already flags where alignment-based
  conservation is unreliable — shallow (<1) or over-deep — see the main README caveat.
- **`.a2m` convention.** Lower-case letters / dots are insert states relative to the
  query; upper-case / dashes are match-state columns. Conservation should be computed
  on match-state columns, and gaps handled explicitly.
